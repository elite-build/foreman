Control Foreman on your other computers

Each computer keeps its own Foreman with its own repos, worktrees, agent logins and terminals. Pair them once. After that, the titlebar lets you switch this window to another computer and use its Foreman as if you were sitting there. Agents, git, scripts, terminals and files all keep running on that computer. This window only sends what you type and shows what happens. Switch back and you're on your own machine again.

It works the same the other way round: from the Mac you can switch to the PC. Both directions use one pairing.

1 · Switching computers from the titlebar

On the Windows PC, working locally. The first thing in the titlebar now says which computer this window is showing. Open it to see your paired computers and what's happening on each.

1 2 3 4 5
  1. The computer chip. It always shows which computer you're driving: This PC here. The ▲ 1 means another computer has something waiting for you, so you don't miss a stalled agent on the Mac.
  2. One row per paired computer, with the same status words used for workspaces: online, how many are running and whether anything needs you. Unreachable computers stay listed but can't be chosen.
  3. Pair a computer… goes to Settings → Computers (screen 4). Each computer gets a shortcut, Ctrl+Alt+1 / 2…, to switch without the mouse.
  4. Everything below the chip (repo rail, workspace list, Automations, Assistant) belongs to the computer that's selected. Switching replaces the whole view. Workspaces from two computers are never mixed in one list.
  5. Needs you, from anywhere. If an agent on the Mac asks for approval while you're on the PC, you get a notification. Open on MacBook Pro switches straight to it.

2 · Driving the Mac from the Windows PC

The same Windows window, switched to MacBook Pro. These are the Mac's repos and workspaces. The agent, the terminal and the iOS simulator all run on the Mac.

1 2 3 4 5 6
  1. The chip now reads MacBook Pro, with a laptop icon instead of a monitor. Where you are is always written out, not shown by colour alone.
  2. The remote banner stays on top of every view while you're on another computer: what's running where, the link's latency, and Back to this PC. It's a standard Callout banner, like the existing cloud-workspace banner.
  3. The workspace header has a MacBook Pro tag, the same slot cloud workspaces use for their provider pill.
  4. Approvals, follow-ups, Stop, checks, commits and PRs all work as they would on the Mac. This is the Mac's agent, using the Mac's Claude login, asking to run a command on the Mac.
  5. Terminals are real shells on the Mac (zsh, /Users/yatin/…), streamed to this window. Keystrokes go there and output comes back.
  6. The footer shows the connection. Settings, Archived and Import in this view act on the Mac's Foreman. This PC's settings stay where they are.

3 · Meanwhile, on the Mac's own screen

The Mac keeps working normally and shows the same live state. You can always tell someone else is connected, and you can disconnect them.

1 2 3 4
  1. A blue Yatin's PC chip (monitor icon; its tooltip and popover say “controlled from”) appears whenever another computer is connected. It sits next to the computer chip, like the phone chip.
  2. Its popover shows who is connected, since when, over which network and with what access. From there you can Make watch-only or Disconnect. Disconnecting stops only the remote view. Agents keep running.
  3. Attribution: messages and approvals that came from another computer are labelled, so the history shows who did what.
  4. Both screens are live at once. You can type on the Mac while the PC watches, or the other way round. There's no lock to take or hand back.

4 · Settings → Computers

Today's “Devices” section (Mac-to-Mac hand-off) becomes Computers. It covers Mac and Windows, and pairing once enables both hand-off and remote control.

1 2 3 4 5
  1. Let paired computers control this one is the host-side switch. Turn it off and paired computers can still hand off work but can't drive this one.
  2. How they reach you: the same two options as phone access. Same network uses a LAN address. Anywhere uses your Tailscale address, so you can drive the Mac at home from the PC at work. There's no Foreman server in between.
  3. When a computer connects: let it in, or ask on this screen first. Asking first is the default.
  4. Access is set per computer: Full control, Watch only (read chats, diffs and terminals; no sending or approving), or Not allowed.
  5. Pairing reuses today's 6-digit code exchange. The code just stops saying “Mac”.

5 · When the link drops

The Mac goes to sleep, or the Wi-Fi drops. The work on the Mac carries on. Only the view freezes.

1 2 3
  1. The banner switches to a warning: ▲ Lost the connection to MacBook Pro. It retries on its own, with Retry now and Back to this PC. If the Mac is asleep with its lid closed, it points to Keep awake on the Mac.
  2. Everything you last saw stays on screen, dimmed and marked last known, so you can still read it. Nothing is presented as current.
  3. Sending and approving are switched off, with the reason given. Nothing is queued quietly on this PC: a message must never run later on a computer you've stopped watching.

6 · The details that change on a remote computer

Anything that touches a file, a port or an app says which computer it acts on.

Decisions to make before building

  1. Switch the whole view, or mix workspaces? These mocks switch the whole app to one computer at a time, with “needs you” alerts across computers. A combined list with a Mac/PC tag on each workspace is possible but busier.
  2. Watch-only mode: worth having in the first version, or only Full control?
  3. Agent credentials stay on the host. The PC never sees the Mac's Claude or GitHub tokens, only results. This rules out “run the Mac's agent with my PC's login”.
  4. What the link carries: today's Mac pairing sends one-off encrypted requests. Remote control needs a lasting, streaming channel (chat events, PTY output) over the same pairing key, plus Windows support for the pairing that's currently Mac-only in its wording.
  5. Previews: tunnel the remote dev server's port to localhost here (card 4), or open it on the remote computer?
